# Пояснення реалізації

## Як читати проєкт

Почніть з `index.html`: у `head` задано кодування, масштабування та підключено спільні файли. У `body` спочатку йдуть шапка й навігація, потім основний вміст і футер. Такий порядок зберігається й на телефоні. Класи HTML відповідають селекторам у `styles.css`.

## Чому використано Grid і Flex

Grid зручно керує рядками та стовпцями. `.hero` на вузькому екрані має одну колонку; від 56rem — дві. `.gallery-grid` змінюється з однієї колонки на дві від 36rem, на три від 72rem. `repeat(3, minmax(0, 1fr))` означає три рівні частки доступної ширини. Нульова мінімальна ширина дає колонкам стискатися без переповнення через мінімальний розмір вмісту.

Flexbox розподіляє елементи вздовж однієї осі. У `.header` логотип і меню рознесено через `justify-content: space-between`. `flex-wrap: wrap` дозволяє меню перейти нижче. Саме меню також переносить посилання. Навігація завжди видима, тому окремий мобільний перемикач не потрібний.

## Mobile-first і точки зламу

Базові правила описують одну колонку. Медіазапити `min-width` додають складнішу структуру, коли з’являється простір:

| Умова | Зміна |
| --- | --- |
| До 36rem | Одна колонка; навігація переноситься за потреби |
| Від 36rem | Вибрані роботи й галерея у дві колонки |
| Від 56rem | Головний екран та інформаційні секції у дві колонки; етапи у три |
| Від 72rem | Галерея у три колонки |

Точки зламу прив’язані до потрібного місця для вмісту. Медіазапит не підвищує специфічність селектора: його правила застосовуються лише за виконання умови й беруть участь у звичайному каскаді.

## Гнучкі розміри

`.wrap { width: min(100% - 2.5rem, 76rem); }` залишає поля на телефоні й обмежує максимальну ширину на великих екранах. `clamp()` задає нижню, бажану та верхню межі розміру заголовка. `rem` залежить від кореневого розміру шрифту. `box-sizing: border-box` включає внутрішні відступи та рамку в задану ширину.

Ралійні зображення мають локальні WebP-версії шириною 640 і 1280px. `srcset` перелічує джерела, а `sizes` підказує їхній розмір у макеті. `max-width:100%` та `height:auto` зберігають адаптивність. `width`/`height` резервують пропорції; `object-fit:cover` дозволяє заповнити головний кадр. SVG використано для значка сайту.

## Доступність

`lang="uk"` повідомляє мову. `alt` описує зображення. `aria-current="page"` позначає поточну сторінку. `:focus-visible` показує фокус клавіатури. Посилання «Перейти до вмісту» дає пропустити шапку. Кнопки фільтрів використовують `aria-pressed`, а кількість робіт оголошується через `aria-live="polite"`.

Нативний `dialog.showModal()` відкриває модальний перегляд із блокуванням взаємодії з фоном. Браузер обробляє Escape та повернення фокусу. FAQ використовує нативні `details` і `summary` без JavaScript. Масштабування сторінки не заборонено.

## Що робить JavaScript

Фільтр порівнює `data-filter` кнопки з `data-category` картки й встановлює `hidden` для зайвих робіт. Дані збільшеного перегляду беруться з уже наявної картки через `textContent`. Жодні дані не надсилаються на сервер. Якщо JavaScript вимкнений, фільтри приховані, а галерея залишається набором звичайних посилань.

## Походження роботи

HTML, CSS, JavaScript, тексти та оформлення підготовлено за допомогою ШІ відповідно до запиту. Зображення створено ImageGen і позначено як ілюстрації. Навчальні матеріали використано для вибору тем пояснень та прийомів верстки. Особисті дані автора не вигадувалися. Перед здачею варто розібрати код і персоналізувати зміст.
