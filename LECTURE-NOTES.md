## 1. Вебтехнології: три мови й один протокол

Джерело: «Л1. Веб-технології.pptx», зокрема слайди 11–24.

**HTML** описує структуру та зміст документа. **CSS** визначає вигляд і розташування. **JavaScript** додає поведінку та реакцію на події. **HTTP** визначає обмін запитами й відповідями між клієнтом і сервером.

### Адреса й завантаження сторінки

URL складається зі схеми, хоста, необов’язкового порту, шляху, параметрів після `?` та фрагмента після `#`. Фрагмент використовується браузером і не надсилається серверу. DNS допомагає знайти IP-адресу за доменним іменем. Домен і хостинг — різні складові.

Після визначення адреси браузер встановлює з’єднання, для HTTPS узгоджує захищений обмін і надсилає HTTP-запит. Сервер повертає статус, заголовки та за потреби тіло відповіді. Браузер будує DOM з HTML, застосовує CSS та виконує JavaScript. Стилі, скрипти й зображення можуть потребувати окремих запитів.

### HTTP

GET отримує ресурс, POST надсилає дані для обробки, PUT замінює представлення ресурсу, PATCH частково змінює його, DELETE видаляє. Класи статусів: 2xx — успіх, 3xx — перенаправлення та пов’язані механізми, 4xx — помилки клієнтського запиту, 5xx — помилки сервера. Приклади: 200, 404, 500.

У лекції текстова форма запиту показана на HTTP/1.1. HTTP/2 використовує бінарне представлення й мультиплексування, HTTP/3 працює поверх QUIC. Семантика методів і статусів зберігається.

### HTML

Елемент може містити початковий тег, атрибути, вміст і кінцевий тег. Порожні елементи на кшталт `img`, `meta`, `input` не мають кінцевого тега. HTML є мовою розмітки.

Мінімальний документ містить `<!DOCTYPE html>`, `html` з мовою, `head` із кодуванням, заголовком і viewport, а також `body`. Семантичні елементи пояснюють призначення частин: `nav` — навігація, `main` — головний вміст, `article` — самостійна публікація, `footer` — завершальна частина. `div` використовується, коли потрібна нейтральна обгортка.

Інструменти розробника допомагають дослідити DOM, активні стилі та мережеві запити. Важливо вміти пояснити код і перевірити його результат, зокрема якщо код згенерований.

## 2. CSS та препроцесори

Джерело: «Л2. CSS.pptx», слайди 4–15 та 18–25.

### Підключення й селектори

CSS можна додати атрибутом `style`, блоком `style` або зовнішнім файлом через `link`. Для кількох сторінок зручно мати спільний зовнішній файл. Правило складається із селектора й декларацій `властивість: значення`.

Селектори вибирають тег, клас або ідентифікатор. Комбінатори описують зв’язки між елементами. Псевдокласи, наприклад `:hover` і `:focus-visible`, залежать від стану. Псевдоелементи `::before` і `::after` дозволяють додати оформлювальні частини.

### Каскад

Серед правил одного походження, шару й важливості порівнюється специфічність: селектори ID мають більшу вагу, ніж класи, а класи — ніж теги. За рівних умов перемагає пізніше правило. Це спрощений практичний випадок каскаду; порядок не можна зводити лише до специфічності. `!important` змінює пріоритет декларації, тому його не варто використовувати як повсякденне виправлення структури стилів.

### Бокс-модель і текст

Елемент має вміст, внутрішні відступи `padding`, рамку `border` і зовнішні відступи `margin`. `box-sizing: border-box` включає padding і border у задані width/height. Margin залишається зовні.

Типографікою керують `font-family`, `font-size`, `font-weight`, `line-height`, `letter-spacing`. Кольори можна задавати іменами, HEX та колірними функціями. Достатня висота рядка й читабельний контраст потрібні незалежно від розміру екрана.

### Flexbox і Grid

Flexbox розташовує елементи переважно вздовж однієї осі. `flex-direction` задає напрямок, `justify-content` — розподіл по головній осі, `align-items` — вирівнювання по поперечній, `flex-wrap` — перенесення. Елементи мають `flex-grow`, `flex-shrink` і `flex-basis`.

Grid працює з рядками й стовпцями. `grid-template-columns` задає колонки, `gap` — проміжки. `fr` розподіляє вільний простір. `repeat()` повторює опис, `minmax()` обмежує розмір. `auto-fit` та `auto-fill` дозволяють визначати кількість колонок за доступною шириною; їхня поведінка відрізняється для порожніх треків.

### Змінні та SCSS

CSS custom properties оголошують як `--accent` і читають через `var(--accent)`. Вони беруть участь у каскаді й можуть змінюватися під час роботи сторінки. Нативна вкладеність дозволяє групувати пов’язані правила.

SCSS — синтаксис препроцесора Sass. Браузеру надходить скомпільований CSS. Змінні SCSS обчислюються під час збірки, на відміну від custom properties у браузері. Міксини дають повторно використовувати блоки з параметрами; цикли генерують правила, модулі організовують код. Для цього невеликого сайту використано звичайний CSS без препроцесора.

## 3. Адаптивна та відгукова верстка

Джерело: «Л.3 Адаптивна та відгукова верстка.pptx», слайди 3–13.

**Adaptive** зазвичай описує кілька макетів для визначених діапазонів. **Responsive** — один гнучкий макет, який підлаштовується до ширини. Практично поєднують гнучкі сітки, масштабовані зображення та медіазапити.

### Viewport і mobile-first

`<meta name="viewport" content="width=device-width, initial-scale=1">` узгоджує ширину viewport із пристроєм. Без нього мобільний браузер може показати зменшену широку сторінку. Не слід забороняти користувачеві збільшення.

Mobile-first починається з простого вузького макета. `@media (min-width: ...)` додає колонки й інші зміни для більшого простору. Точки зламу обирають там, де вміст стає незручним, а не за назвою конкретного телефона. Медіазапити можуть перевіряти також reduced motion, hover, схему кольорів або друк.

### Гнучка сітка й одиниці

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(16rem, 100%), 1fr));
  gap: 1rem;
}
h1 { font-size: clamp(2rem, 1rem + 3vw, 4rem); }
```

`rem` пов’язаний із кореневим шрифтом, `em` — із розміром шрифту відповідного контексту, `%` — із залежною від властивості базою, `vw` — із шириною viewport, `dvh` — з його динамічною висотою. `ch` корисний для обмеження довжини рядка. Пікселі доречні для тонких рамок.

### Зображення й контейнерні запити

`max-width: 100%; height: auto` утримує зображення в межах контейнера. Для растрових файлів `srcset` і `sizes` допомагають обрати відповідну роздільність. `picture` дозволяє задати альтернативні джерела. `width`/`height` резервують співвідношення сторін, `loading="lazy"` відкладає завантаження другорядних зображень, `alt` передає їхній зміст.

Container queries перебудовують компонент залежно від ширини його контейнера. Для цього обгортці задають `container-type: inline-size`, а правила нащадків описують у `@container`. Медіазапит перевіряє viewport, контейнерний запит — конкретний контейнер. У готовому сайті для прозорості навчального прикладу використано медіазапити.

### Доступність і перевірка

Перевіряють відсутність горизонтальної прокрутки на 320 CSS px, збільшення тексту до 200%, достатній контраст, розміри інтерактивних елементів і роботу клавіатурою. Фокус має бути видимим. Порядок HTML повинен залишатися логічним після перебудови макета. Для елементів керування у цьому проєкті використано мінімальну висоту 44px.
